# AI ინტერვიუერი — სამუშაო პროცესების ანალიზის პროტოტიპი (Python + Gemini)

პროტოტიპი (ეტაპი 1), რომელიც ესაუბრება თანამშრომელს მისი სამუშაო პროცესების, პრობლემებისა და
განმეორებადი ამოცანების შესახებ, follow-up კითხვებით უღრმავდება რეალურ საჭიროებას და საბოლოოდ
აგენერირებს სტრუქტურირებულ ჩამონათვალს — სად არის შესაძლებელი პროცესის გაუმჯობესება, ავტომატიზაცია
ან AI-ის გამოყენება.

**Backend: Python (Flask).** **Frontend: ერთი HTML ფაილი**, რომელშიც ჩაშენებულია CSS და JavaScript
(`static/index.html`) — დამატებითი ფაილების ან framework-ის გარეშე.

---

## როგორ არის AI ინტეგრირებული

- გამოიყენება Google-ის ოფიციალური Python SDK — [`google-genai`](https://pypi.org/project/google-genai/).
- `app.py`-ში იქმნება `genai.Client(api_key=...)`, სადაც `api_key` მოდის `GEMINI_API_KEY`
  environment variable-იდან (არასოდეს კოდში).
- **საუბრის დროს** (`/api/chat`): ყოველ ტურზე ვქმნით ახალ `client.chats.create(...)` სესიას და
  ვაწვდით **მთელ წინა ისტორიას** (`history=...` პარამეტრში) — არა მხოლოდ ბოლო შეტყობინებას.
  ეს არის მთავარი მექანიზმი, რომელიც უზრუნველყოფს, რომ **AI-მ არასდროს დაკარგოს კონტექსტი**:
  Gemini ყოველთვის ხედავს საუბრის დასაწყისიდან მოყოლებულ სრულ ისტორიას, დეპარტამენტისა და
  როლის კონტექსტთან ერთად (რომელიც system instruction-შია ჩაშენებული).
- **ანალიზის გენერირებისას** (`/api/summary`): ცალკე მოთხოვნა იგზავნება
  `response_mime_type="application/json"` კონფიგურაციით — ე.წ. Gemini-ის "JSON mode", რომელიც
  აიძულებს მოდელს დააბრუნოს მხოლოდ ვალიდური, წინასწარ განსაზღვრული სტრუქტურის JSON
  (იხ. `build_summary_system_prompt()` ფუნქცია `app.py`-ში — იქ არის ზუსტი სქემა).

### სად ინახება დასკვნა?

დასკვნა **JSON ფორმატშია** და ორ ადგილას ხვდება:

1. **სერვერზე, დისკზე** — `/api/summary`-ის დამუშავებისას ავტომატურად იწერება ფაილად
   საქაღალდეში `data/summaries/`, სახელით
   `<UTC-დროის-შტამპი>_<დეპარტამენტი>_<როლი>.json` (მაგ. `20260908T101530Z_gayidvebi_menejeri.json`).
   ფაილი შეიცავს დეპარტამენტს, როლს, სრულ ტრანსკრიპტს და სტრუქტურირებულ ანალიზს ერთად.
2. **ბრაუზერში, ვიზუალურად** — frontend იღებს იმავე JSON-ს API-ის პასუხში და თარგმნის მას
   ბარათებად (თითო finding = ერთი ბარათი, კატეგორიისა და პრიორიტეტის ტეგებით).

> **⚠️ მნიშვნელოვანი შენიშვნა Render-ის შესახებ**: Render-ის უფასო ტარიფზე დისკი **ეფემერულია** —
> `data/summaries/`-ში დაწერილი ფაილები **წაიშლება** ყოველი ახალი დეპლოის ან სერვერის
> გადატვირთვისას. ეს მისაღებია პროტოტიპის ტესტირებისთვის, მაგრამ production-ისთვის საჭირო
> იქნება მუდმივი მონაცემთა ბაზა (PostgreSQL, და ა.შ.) ან Render-ის fee ტარიფის persistent disk.
> ეს საკითხი უკვე ჩამოთვლილია "Production მზაობის ანალიზი" დოკუმენტში.

### დეპარტამენტისა და პოზიციის სავალდებულო შეკითხვა

Frontend-ის საწყისი ფორმა **არ უშვებს** საუბრის დაწყებას, სანამ დეპარტამენტისა და პოზიციის ველები
შევსებული არ არის (ღილაკი გამორთულია, სანამ ორივე ველი ცარიელია). ეს მონაცემი შემდეგ:
- ინახება ყოველი მოთხოვნის `context` ობიექტში და გადაეცემა Gemini-ს system instruction-ის სახით;
- ჩაიწერება საბოლოო JSON დასკვნაშიც (`department`, `role` ველები);
- backend-ის მხარესაც მოწმდება (`/api/chat` და `/api/summary` დააბრუნებენ 400 შეცდომას, თუ ეს
  ველები ცარიელია) — ორმაგი დაცვა, frontend-ზე დაყრდნობის გარეშე.

### კონტექსტის დაუკარგაობა

- **სერვერს არ აქვს "მეხსიერება"** საკუთარ თავში — ის მთლიანად სტატელესია (stateless). ამის
  ნაცვლად, **ბრაუზერი** ინახავს სრულ საუბრის ისტორიას (`localStorage`-ში, გასაღებით
  `ai_interviewer_session_v1`) და ყოველ მოთხოვნაზე მთელ ისტორიას უგზავნის სერვერს.
- სერვერი ამ სრულ ისტორიას გადასცემს Gemini-ს (`history=...`) ყოველ ჯერზე ხელახლა — ანუ
  კონტექსტი არასდროს "იჭრება" შუაში.
- `localStorage`-ის წყალობით, **გვერდის შემთხვევითი განახლებაც კი არ შლის საუბარს** — ბრაუზერის
  ხელახლა გახსნისას საუბარი აღდგება იქიდან, სადაც შეწყდა.

## ლოკალურად გაშვება

1. დააკლონეთ რეპოზიტორია და შედით საქაღალდეში:

   ```bash
   git clone <თქვენი-repo-URL>
   cd ai-interviewer-py
   ```

2. შექმენით ვირტუალური გარემო და გაააქტიურეთ (რეკომენდებულია):

   ```bash
   python3 -m venv venv
   source venv/bin/activate      # Windows-ზე: venv\Scripts\activate
   ```

3. დააინსტალირეთ დამოკიდებულებები:

   ```bash
   pip install -r requirements.txt
   ```

4. შექმენით `.env` ფაილი `.env.example`-ის მაგალითზე დაყრდნობით:

   ```bash
   cp .env.example .env
   ```

   გახსენით `.env` და შეავსეთ:

   ```
   GEMINI_API_KEY=თქვენი_გასაღები_აქ
   ```

   **მნიშვნელოვანია**: `.env` ფაილი არასდროს აიტვირთება git-ში — ის უკვე შეტანილია `.gitignore`-ში.
   არასოდეს ჩაწეროთ გასაღები პირდაპირ კოდში.

5. გაუშვით სერვერი:

   ```bash
   python app.py
   ```

6. გახსენით ბრაუზერში: **http://localhost:3000**

## Render-ზე გაშვება

### ვარიანტი A — Blueprint (`render.yaml`) გამოყენებით

1. აიტვირთეთ პროექტი GitHub-ზე (იხ. ზემოთ).
2. [Render Dashboard](https://dashboard.render.com/)-ში აირჩიეთ **New → Blueprint**.
3. მიუთითეთ თქვენი GitHub რეპოზიტორია — Render ავტომატურად წაიკითხავს `render.yaml`-ს
   (runtime: Python, build: `pip install -r requirements.txt`, start: `gunicorn app:app`).
4. როცა მოგთხოვთ, ჩაწერეთ `GEMINI_API_KEY`-ის მნიშვნელობა.
5. დააჭირეთ **Apply** / **Deploy**.

### ვარიანტი B — ხელით, Web Service-ის შექმნით

1. [Render Dashboard](https://dashboard.render.com/)-ში აირჩიეთ **New → Web Service**.
2. დააკავშირეთ თქვენი GitHub რეპოზიტორია.
3. მიუთითეთ პარამეტრები:
   - **Runtime**: Python 3
   - **Build Command**: `pip install -r requirements.txt`
   - **Start Command**: `gunicorn app:app --bind 0.0.0.0:$PORT`
4. "Environment" სექციაში დაამატეთ environment variable:
   - Key: `GEMINI_API_KEY`
   - Value: თქვენი გასაღები (Google AI Studio-დან)
5. (არასავალდებულო) დაამატეთ `GEMINI_MODEL`, თუ გინდათ სხვა მოდელის გამოყენება.
6. დააჭირეთ **Create Web Service**.

დეპლოის დასრულების შემდეგ Render მოგცემთ საჯარო URL-ს (მაგ. `https://ai-interviewer.onrender.com`).

- `data/summaries/`-ში ინახება რეალური თანამშრომლების საუბრები — ეს საქაღალდე გამორიცხულია
  git-იდან და production-ში საჭიროებს დამატებით წვდომის კონტროლს (იხ. "Production მზაობის ანალიზი").

  მუდმივი მონაცემთა ბაზა.

- არ არის რამდენიმე დეპარტამენტის შედეგების შედარების დაშბორდი.
- API-ის გამოძახებებზე rate limiting არ არის კონფიგურირებული.
- არ არის ავტომატური ტესტები.
